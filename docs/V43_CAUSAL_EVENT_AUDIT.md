# V4.3 因果评价与正式晋级契约

修订：v4.3-causal-event-20260913。V4.2 学习分兼容保留；V4.3 全审计新增独立强制证据门槛。非 PIT 仍只作披露，不作否决项。

1. fwd_h 使用全市场质量有效观测构成的统一交易日历：t+1 开盘至 t+1+h 开盘，不能跳过单只证券的停牌/缺行情记录。缺端点就是 null。该日历不是额外采购的交易所官方日历。
2. 层末 purge：标签结束日期必须落在本层内；除第一训练层之外，每层开头 embargo h 个市场交易日。因子先在完整历史上计算，保留滚动预热；评价日期切片在计算后完成。调仓日期只由日历决定，不因信号或收益缺失改变。选股排名、权重不使用未来标签是否存在；选中股票缺少标签时，向量收益不具备完整证据资格。
3. 一次完整审计固定同一个内存面板、原始分区内容 SHA256、代码文件内容、Git commit/dirty diff、表达式、配置和实际起止日期。内容寻址副本保存在 var/audit_snapshots；不硬链接到可被下载器修改的原文件。原始分区与已加载面板不一致会拒绝审计。
4. 全审计强制运行 Python step_event_v2：HOLDOUT、Vault 和 2020 至面板最后实际日期三段。前两段沿用 h 日 embargo。固定方向、股票池、持有期、资本、头尾比例与借券参数。事件成本为基础 bps 执行滑点加市场手续费和借券成本，不声称与向量简化成本精确等价。按日费后 Sharpe、正收益、MDD、换手、完整性与输入证明独立设门槛；事件异常或未执行不能通过。终点尝试清仓，不能保证停牌持仓一定成交。
5. 正式生命周期还要求双盲审查、当期评级和真实试验账本 DSR/PBO。每次实际评价记录所有尝试方向的带日期、未归一化、费后训练收益路径。历史缺失、不同比较契约或样本不足返回 INSUFFICIENT_DATA，不使用赢家样本或压缩指纹代替原收益。DSR 使用每期 Sharpe；PBO 使用 Sharpe 选优、全部对称分割。评级和事件验证结果不进入研究提示词。
6. 新 API rank_ic_mean/rank_icir 明确为 Spearman RankIC；pearson_ic_mean/pearson_icir 明确为原值 Pearson。旧 ic_mean/icir 仅保留为已标注的 RankIC 兼容别名，界面改为正确名称。交易 PF、胜率以已平仓批次为单位（部分平仓也是批次），不是每只股票的完整生命周期；未平仓不计入胜率/PF，单独报告数量和浮盈亏。融资/借券费用仍计入每日组合净值，未分摊到平仓批次的部分明确披露，不能把该 PF 解释成含全部资金成本的组合 PF。

评级覆盖训练时期，属于完整历史诊断，不是独立样本外证据。统计置信、账本 PASS 和历史盈利均不代表未来收益保证。
