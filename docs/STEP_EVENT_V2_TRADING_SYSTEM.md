# Step Event V2 交易系统回测协议

`step_event_v2` 是 FactorFactory 的状态化日线交易系统模拟协议。向量引擎仍只用于快速筛选，最终结果必须由事件账本复核。

## 因果时间轴

1. t日收盘计算因子并创建目标仓位订单。
2. t+1开盘先处理公司行动和已有持仓的跳空风险，再执行调仓订单。
3. 使用当日原始最高价/最低价检查站立止损和止盈；移动锚点只在当日收盘后更新。
4. 收盘计提借券费、融资利息，检查组合风控，再生成下一交易日订单。

成交容量使用此前20个交易日ADV。开盘时尚未知的当日总成交量不得作为容量依据。

## 个股退出

- 固定比例止损、固定比例止盈
- 百分比移动止损
- 初始ATR止损、ATR止盈、ATR移动止损
- 盈利达到阈值后的保本止损
- 最长持有交易日
- 组合最大回撤和单日损失退出

组合级退出使用有状态协议：`armed → liquidating → cooldown → rearmed`。首次越过阈值时清仓，冷却期间禁止重新入场；持仓清零且冷却结束后，以当时NLV重置组合风控高水位，并从下一交易日重新允许建仓。空仓状态不会继续用退出前的历史峰值反复触发回撤规则，因此不会形成永久现金锁死。结果同时报告触发次数、重新武装次数、风险关闭交易日和区间末连续空仓日数。

`portfolio_stop_drawdown_pct` 是收盘触发阈值，不是最大回撤保证。订单到下一交易日开盘才执行，跳空、流动性限制和费用可能使单个风控周期的实际回撤超过阈值；多个周期重新武装后，全区间相对最初历史峰值的标准最大回撤也可能高于单周期阈值。结果分别报告标准 `max_dd` 和 `max_portfolio_risk_cycle_drawdown`。

跳空越过触发线时按开盘价成交。只有日线OHLC且止损、止盈同日均被触及时，默认使用保守顺序，即先止损；该事件写入 `intrabar_ambiguities`。

## 市场与账户边界

- A股买入按100股整手；当日新买数量不可当日卖出，风险退出自动续挂；涨跌停或停牌代理可以拒绝成交。
- 美股纯多默认现金账户，禁止负现金。多空默认保证金账户，计提借券费和负现金融资利息。
- `long_gross_target + short_gross_target` 是配置目标；引擎以 `max_gross_leverage × (1 - cash_buffer_fraction)` 作为运行上限，按比例缩放多空腿，显式预留缓冲带。
- 每笔增仓成交均以实际成交价、费用和滑点投影成交后NLV与总杠杆；超过 `max_gross_leverage` 的增仓部分按整手/整股截断。减仓、回补和平仓不受该限制。
- 调仓先执行降低总风险的订单，再执行增加总风险的订单。目标仓位还会在实际开盘价下批量重算，避免隔夜跳空导致超额建仓。
- 若已有仓位因跳空、费用或部分成交残余在开盘被动超过硬上限，引擎会立即按比例自动减仓至恢复目标。已修复事件保留审计记录但不判失败；流动性或交易限制导致无法修复时，`gross_leverage_violations` 才大于零并使完整性检查失败。
- 连续缺少行情达到阈值的多头按零值减记，避免最后价格永久形成幽灵资产。

## 审计产物

- `settlement_statement.parquet/csv`：逐笔成交与费用
- `event_ledger.parquet`：完整事件序列
- `daily_ledger.parquet`：逐日现金、敞口和净值
- `round_trip_ledger.parquet/csv`：完整交易、净盈亏、持有期、MAE/MFE和退出原因
- `manifest.json`：配置、统计、完整性检查和文件SHA256

所有新参数均被冻结在回测记录和manifest中。关闭退出规则时仍保留现金、杠杆、因果流动性和幽灵持仓修复；因此v2结果不应与旧v1混为同一协议。

杠杆审计至少包括控制前/控制后的每日开盘杠杆、逐笔成交后的杠杆、被截断订单数、开盘触线次数、自动去杠杆次数，以及每次触线的日期、前后值、硬上限、减仓单数和是否修复。完整性门槛只依据未修复超限，不通过调大容忍度掩盖问题。
