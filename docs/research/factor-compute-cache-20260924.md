# 因子计算缓存与多配置评价（2026-09-24）

## 实现范围

1. **统一因子列缓存**：训练评价、完整向量审计和 Python 事件回测共同调用 `factor_compute_cache.factor_column`。缓存只包含因果因子值，不包含标签、方向选择、分数或入库结果。
2. **公共 DSL 子表达式缓存**：以精确 AST 为键，共享滚动统计、截面 rank 等中间列；每个表达式最多保留四个中间节点。全局反号不会被归为相同计算结果，缓存命中仍重新校验完整 DSL。
3. **同表达式多配置评价**：`evaluate_batch` 固定一份输入面板，分别运行股票池、持有期、方向策略与成本配置；共享计算列，但不共享配置的评价结果，也不自动选冠军。

现有研究和回测调用自动接入缓存，不必修改已保存任务。新增批量入口用于明确提交的配置，不自动扩大原任务搜索预算。缓存适用训练与回测的兼容上下文，而不是声称不同输入区间可以无条件共享。

## 一致性边界

- 键绑定冻结数据快照、源代码、DSL/缓存实现版本、Polars 版本、市场、字段白名单、行布局及准确的源数据起止日期。
- 不截断滚动预热，不先筛 Top-N 再做截面 rank，不重排行序，不降低 float64 精度。
- 有限预热回测与全历史评价保留不同键；不同区间重新计算，避免浮点滚动路径差异。
- 未冻结或不匹配冻结面板对象的输入使用原实现。
- HOLDOUT、Vault 和评级结果不缓存到训练反馈，也不改变原隔离层、正式因子生命周期或门槛。
- 全进程 RAM LRU 默认上限 384 MiB，不是每任务各占 384 MiB；它限制持久缓存，不代表整个计算进程的峰值内存。
- 同一个完整表达式的并发首次计算有锁保护，避免重复物化。中间列只在 RAM 中保存。
- 可选磁盘缓存默认关闭。启用后保存校验哈希、原子落盘、受预算淘汰；损坏或不可用则重新计算，不能生成伪造结果。

## 接口与审计

`GET /api/compute-cache` 返回内存占用、命中、淘汰、因子物化与中间列复用计数。

`POST /api/evaluations/batch` 示例：

```json
{
  "experiment_id": 53,
  "expression": "rank(returns(close,20))",
  "tasks": [
    {"name": "Top500-5d", "universe_n": 500, "horizon": 5, "portfolio_mode": "long_only"},
    {"name": "Top1500-10d", "universe_n": 1500, "horizon": 10, "portfolio_mode": "long_only"}
  ]
}
```

任务 ID 应使用对应服务的已有实验。每批 1–32 个配置，只运行训练安全层。开始计算前登记每个配置的 Trial；结束保存双向原始收益证据。缓存命中也登记试验，不减少多重检验次数。失败/中断的尝试不会被删除或当作通过。进度进入已有 `/api/compute-tasks`，结果明确 `formal_eligible=false`。

批量 API 不等于新增一批正式候选，不调用完整审计，不自动修改任务、方向、因子库或搜索预算。调用方直接使用 Python 函数时必须自己登记试验；离线基准脚本不污染生产研究账本。

## 验证方法

`tests/test_factor_compute_cache.py`：精确列值对齐、不同输入区间、跨版本失效、字段校验、缓存副本隔离、内存淘汰、磁盘校验、并发去重和批量配置独立性。

`tests/test_batch_evaluation_api.py`：隔离数据库会话验证请求限制、先登记后计算、部分失败保留、原始证据入账，不连接生产数据库。

真实数据脚本：

```sh
.venv/bin/python scripts/benchmark_factor_compute_cache.py --output var/reports/NEW-NAME/report.json
```

覆盖美股纯多、美股多空、A 股纯多；每种覆盖三配置训练、相似表达式、完整向量审计、普通与进阶风控事件回测。行情先预热再测缓存开关，避免把磁盘冷加载误算为加速。比较包括未舍入收益证据、评分、完整交易/日账本和诊断；仅排除计时、缓存诊断及出处包装字段。

初始报告 `var/reports/factor-compute-cache-20260924/report.json` 保留原样：全部新旧结果一致，但无杠杆余量的美股多空样例在 2026-09-22 去杠杆后仍为 2.00421719×，高于 2×上限，新旧均 FAIL。不能把“实现等价”说成“所有策略通过风控”。

独立重测报告 `var/reports/factor-compute-cache-20260924-headroom/report.json` 明确将两侧目标各设为 0.9、硬上限仍为 2，只用于增加一组带余量的测试；未修改服务默认风控或已有回测。保留原失败样例及报告，不放宽门槛。

| 三配置评价 | 关闭缓存 | 首次缓存 | 缓存命中 | 命中加速 |

| 美股纯多 | 2.685 s | 1.865 s | 1.397 s | 1.92× |
| 美股多空 | 2.970 s | 2.023 s | 1.436 s | 2.07× |

本轮共 15 组真实数据对照均精确一致，6 组带余量/纯多事件回测均账本 PASS。相关表达式评价由 0.957/0.992/1.168 s 降至 0.848/0.889/0.980 s。事件回测中因子物化约快 1.41–1.83×；事件回放与诊断仍占主要时间，总耗时增益较小，个别复杂样例在噪声下略慢。以上是单次配对性能样例，不是整个网站速度或所有 DSL 的保证。

## 回退

服务启动默认：

```text
FF_FACTOR_COMPUTE_CACHE=1
FF_FACTOR_CACHE_MB=384
FF_FACTOR_CACHE_DISK_MB=0
```

将 `FF_FACTOR_COMPUTE_CACHE=0` 后重启即恢复旧物化路径。缓存是可丢弃派生数据，不迁移数据库，不改原始行情，不影响已保存研究记录。
